<h2 id="presets" class="h2-display">Opt in to interface density</h2>

<DocText>Density changes whitespace, not display resolution. The presets are adjustable design choices: compact <code>0.75</code>, comfortable <code>1</code>, spacious <code>1.25</code>. They inherit into descendants; an inner density attribute starts a new density context. Every code block on this page shows exactly the classes that render the demo above it - only the demo's decorative colors are omitted.</DocText>

```html example schema="none"
<div class="flex flex-wrap gap-4" data-demo="density">
  <div data-density="compact" class="stack demo-outline p-3" style="flex:1;min-width:10rem;">
    <p class="demo-label demo-label-inline">>compact - 0.75×</p>
    <div class="demo-tile p-4" data-variant="muted">p-4</div>
    <div class="demo-tile p-4" data-variant="muted">p-4</div>
  </div>
```

<h2 id="advanced" class="h2-display">Real world: a dense data table</h2>

<DocText>The same four records - name, role, last modified - rendered twice with identical markup; only the density attribute changes. In <code>compact</code> the panel's <code>p-4</code> padding, the <code>stack</code> gap and each row's <code>gap-2</code> shrink to 0.75×; in <code>spacious</code> they grow to 1.25×. The avatars (<code>size-8</code>), the font sizes and the <code>ms-auto</code> date alignment do not move: density scales the whitespace between and around the rows, never the type or the geometry. That is what makes a compact mode safe to offer on data-heavy screens - rows pack tighter without shrinking text below readability.</DocText>

<h2 id="component-density" class="h2-display">Components with native density</h2>

<DocText>Beyond the utility scale above, the components whose information density a user actually dials in implement <code>data-density</code> themselves - set it on the component root and their internal whitespace scales with the same <code>0.75 / 1 / 1.25</code> ratio, <code>comfortable</code> being identical to the unsized default. Each component page shows the three steps side by side:</DocText>

<DocText>Components already covered by a dedicated size ladder (Button, Input, Badge, …) deliberately stay out: their compactness is the size axis, and stacking a second whitespace axis on the same padding would make the two fight. Density stays the policy for <em>collections and surfaces</em>; sizes stay the policy for <em>controls</em>.</DocText>

<h2 id="custom-density" class="h2-display">Customize a context</h2>

```css
.dense-inspector { --layout-density: 0.9; }

/* Component-owned opt-in recipe. No changes to existing .btn rules. */
.inspector-action {
  min-inline-size: 44px;
  min-block-size: 44px;
  padding-inline: calc(var(--size-base) * 3 * var(--layout-density));
}
```


<DocText>Use a valid nonnegative number. Numeric spacing clamps negative density to zero; invalid CSS token types are not runtime-validated. Named size aliases stay geometric. Do not express density by changing the root font size or devicePixelRatio.</DocText>

<h2 id="input-policy" class="h2-display">Pointer capability is a separate policy</h2>

```css
.inspector-action {
  min-inline-size: 44px;
  min-block-size: 44px;
}

@media (any-pointer: coarse) {
  .inspector-action { padding-inline: 1rem; }
}
```


<DocText>The example already keeps a 44px target baseline; the media query only adds breathing room. <code>any-pointer: coarse</code> can detect an available coarse pointer on a hybrid device, but it is not a complete description of a user’s access needs. Keep controls usable without that signal. <a href="https://www.w3.org/TR/mediaqueries-4/#any-input" target="_blank" rel="noopener">Media Queries: available pointer capabilities</a></DocText>

<DocText>The AA target-size criterion is 24 × 24 CSS pixels with exceptions; the enhanced AAA criterion uses 44 × 44 with exceptions. Check actual target geometry, not just icon dimensions. <a href="https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html" target="_blank" rel="noopener">WCAG 2.2: Target Size (Minimum), AA</a> · <a href="https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html" target="_blank" rel="noopener">WCAG 2.2: Target Size (Enhanced), AAA</a></DocText>
