<H2>1 - Tokens: the values every part reads</H2>

<DocText>The theme is a set of CSS custom properties on <code>:root</code> (and the same keys with dark values on <code>.dark</code>), in the shape <a class="link" href="https://tweakcn.com" target="_blank" rel="noopener">tweakcn</a> exports. A component never names a colour, a radius or a shadow - it reads a token, so a theme swap or dark mode reaches every component at once. These are the tokens the Toggle reads:</DocText>

<CodeWindow lang="css" title="theme/utils/default-semantic-tokens.css (the keys the Toggle reads)" mb="1.5rem" code={":root {\n  --accent:            oklch(0.9700 0 0);   /* pressed surface */\n  --accent-foreground: oklch(0.2050 0 0);   /* pressed text */\n  --muted:             oklch(0.9700 0 0);   /* hover surface */\n  --muted-foreground:  oklch(0.5560 0 0);   /* resting text */\n  --ring:              oklch(0.7080 0 0);   /* focus ring */\n  --radius:            0.625rem;\n  --radius-md:         calc(var(--radius) - 2px);\n  --font-sans:         ui-sans-serif, system-ui, sans-serif;\n}\n.dark { /* the same keys, dark values */ }"} />

<H2>2 - Markup: one class, data attributes, native semantics</H2>

<DocText>The HTML is a native element with one base class that says what it is. Variants and sizes are <code>data-*</code> attributes (the <DocLink href="data-attribute-api.html">Data Attribute API</DocLink>), never modifier classes, and the state is a native or ARIA attribute - here <code>aria-pressed</code>, which is also what assistive technology reads.</DocText>

<CodeWindow lang="markup" title="the markup you write" mb="1.5rem" code={"<button class=\"toggle\" aria-pressed=\"false\" aria-label=\"Bold\">\n  <i data-lucide=\"bold\"></i>\n</button>\n\n<button class=\"toggle\" data-variant=\"outline\" data-size=\"sm\" aria-pressed=\"true\">\n  Italic\n</button>"} />

<H2>3 - Stylesheet: the class reads the tokens</H2>

<DocText>Every component stylesheet lives in <code>@layer components</code> and nests its variants, sizes and states under the base class. It reads tokens through <code>var(--*)</code> and derives hover colours with <code>color-mix()</code> - no hardcoded palette, so the same file renders every theme. The pressed look is the <code>aria-pressed="true"</code> attribute the markup already carries.</DocText>

<CodeWindow lang="css" title="components/toggle/toggle.css (excerpt)" mb="1.5rem" code={"@layer components {\n  .toggle {\n    display: inline-flex;\n    align-items: center;\n    justify-content: center;\n    gap: 0.5rem;\n    font-size: 0.875rem;\n    font-weight: 500;\n    font-family: var(--font-sans);\n    border-radius: var(--radius-md);\n    border: 1px solid transparent;\n    background: transparent;\n    color: var(--muted-foreground);\n    height: 2.25rem;\n    padding: 0 0.5rem;\n\n    &:hover:not(:disabled) { background-color: var(--muted); }\n\n    &[aria-pressed=\"true\"] {\n      background-color: var(--accent);\n      color: var(--accent-foreground);\n\n      &:hover:not(:disabled) {\n        background-color: color-mix(in oklch, var(--accent) 85%, var(--foreground));\n      }\n    }\n\n    &:focus-visible { outline: 2px solid var(--ring); outline-offset: 2px; }\n    &:disabled { opacity: 0.5; cursor: not-allowed; }\n\n    &[data-variant=\"outline\"] { /* ... */ }\n    &[data-size=\"sm\"] { /* ... */ }\n  }\n}"} />

<H2>4 - Script: only what HTML and CSS cannot do</H2>

<DocText>Most components stop at the stylesheet. The Toggle needs one thing the platform does not give a button: flipping <code>aria-pressed</code> on click. Its module finds every <code>.toggle</code> through <code>df$</code> (the core runtime: <a class="link" href="https://www.npmjs.com/package/defuss-query" target="_blank" rel="noopener">defuss-query</a> for selection and events, <a class="link" href="https://www.npmjs.com/package/defuss-morph" target="_blank" rel="noopener">defuss-morph</a> for markup), guards against initializing twice, binds the <DocLink href="state-api.html">State API</DocLink> so <code>el.api.setState('pressed')</code> and <code>el.store</code> work on every instance, and watches the document so elements added later initialize too. The attribute the script writes is the one the stylesheet reads - the script never styles anything.</DocText>

<CodeWindow lang="javascript" title="components/toggle/toggle.js (excerpt)" mb="1.5rem" code={"function init() {\n  dfDollar('.toggle:not([data-init]):not(.toggle-group .toggle)').each((_i, toggle) => {\n    dfDollar(toggle).data('init', '');                 // the double-init guard\n    toggle._defaultPressed = dfDollar(toggle).attr('aria-pressed') || 'false';\n    // el.store + el.api: $('#my-toggle').api.setState('pressed')\n    bindComponent(toggle, toggleApi, { name: toggle._defaultPressed === 'true' ? 'pressed' : 'default', config: {} });\n    dfDollar(toggle).on('click', () => {\n      dfDollar(toggle).attr('aria-pressed', String(dfDollar(toggle).attr('aria-pressed') !== 'true'));\n    });\n  });\n}\n\ninit();\nnew MutationObserver(init).observe(document, { childList: true, subtree: true });"} />

<H2>5 - Component State API: named states in a store</H2>

<DocText>Every component with a script exposes its states by name. Each element gets <code>el.api.setState(name, config)</code>, <code>el.api.getState()</code> and <code>el.api.render(state)</code>, and <code>el.store</code>: a <a class="link" href="https://www.npmjs.com/package/defuss-store" target="_blank" rel="noopener">defuss-store</a> store of the state's name and config. The store follows every change, including the ones a user makes with a click, so a subscriber observes the component without polling; writing to the store applies the state as <code>setState()</code> does. A page or another component can therefore drive any component from outside and react to its changes through this API and the component's events, without knowing how it is built.</DocText>

<DocText><code>setState()</code> applies a state to the live element through <code>df$</code>: attributes through defuss-query, markup through <a class="link" href="https://www.npmjs.com/package/defuss-morph" target="_blank" rel="noopener">defuss-morph</a>, which patches the existing DOM in place instead of replacing it. <code>render(state)</code> returns the element's markup in any state, as a string, built by the same function, so the UI that <code>setState()</code> produces and the markup <code>render()</code> describes cannot drift apart. The end-to-end test of every interactive component checks that they agree.</DocText>

<DocText>Some components add methods for interactions that a single state does not cover: <code>df$.shadcn.toast.show()</code> raises a toast, <code>df$.shadcn.chart.deck()</code> binds charts to a presentation, <code>df$.shadcn.diagram.build()</code> renders a diagram from JSON. Each component's page documents its whole API.</DocText>

<DocText>defuss-store is a micro-store for backing data that can also persist a store to <code>localStorage</code> or <code>sessionStorage</code>. Every component gets its store without extra code, and the shared layer's <code>persisted()</code> (<code>df$.store</code> for pages) adds the persistence: the big-data components keep their sort and filters this way by default, and these docs keep every remembered choice.</DocText>

<DocText>Every example on these pages runs in the <DocLink href="code-example.html">HTML Preview Editor</DocLink>, so a component's behavior can be watched and tested where it is documented. Its State tab is generated from the component's schema and sets any state value directly; the example below binds the Toggle's.</DocText>

```html example label="The State API, live" component="toggle" hint="Open the State tab: it sets the pressed state through the same API. Press the toggle and the tab follows the click."
<button class="toggle" aria-pressed="false" aria-label="Bold"><i data-lucide="bold"></i></button>
```

<H2>6 - Skill and schema: the component described</H2>

<DocText>Two more files ship beside the stylesheet and the script. The <DocLink href="component-skills.html">component skill</DocLink> (<code>component-skill.md</code>) is the markup reference an agent reads before writing the HTML: the native basis, the structure, the variants, the ARIA and the states. The schema (<code>toggle.schema.json</code>) is the machine contract of the states: their names, types and defaults, how each is set and observed on the DOM - the docs' State tab is generated from it, and the verifier compares every page's States table against it.</DocText>
