  Explicit, service-level privacy choices - and the scripts and embeds they govern stay inert until a service is allowed. Built from the library: a <DocLink href="dialog.html">Dialog</DocLink> holding <DocLink href="button.html">Buttons</DocLink>, a <DocLink href="select.html">Select</DocLink>, <DocLink href="tabs.html">Tabs</DocLink>, <DocLink href="checkbox.html">Checkbox</DocLink> rows and <DocLink href="badge.html">Badges</DocLink>. Accept and reject weigh the same; edits stay a draft until saved; choices are versioned, expire and fail closed; English and German.
</PageHeader>

<script>
  document.addEventListener('DOMContentLoaded', () => {
    const consent = df$('#gate-demo').get(0);
    const video = df$('#gate-video').get(0);
    const frame = df$(video).find('iframe').get(0);
    const source = frame.dataset.consentSrc;
    let wantsToPlay = false;

    // allowed: autoplay from now on - the consent runtime (re)loads the source
    const play = () => {
      df$(frame).attr('data-consent-src', `${source}&autoplay=1`);
      consent.api.updateTagsActivation();
      video.api.setState('playing');
    };

    // the play button asks first - capture runs before the showcase's own handler
    df$(video).on('click', (e) => {
      if (!e.target.closest('.mk-showcase-play')) return;
      e.stopPropagation();
      if (consent.api.isServiceAccepted('youtube')) return play();
      wantsToPlay = true;
      consent.api.setState('services');
    }, { capture: true });

    df$(consent).on('cookie-consent:change', (e) => {
      const { acceptedServices } = e.detail.state;
      df$('#gate-log').text(`${e.detail.reason}: ${acceptedServices.join(', ')}`);
      if (acceptedServices.includes('youtube')) {
        if (wantsToPlay) { wantsToPlay = false; play(); }
      } else {
        // withdrawn: the runtime unloaded the player - the poster returns
        wantsToPlay = false;
        df$(frame).attr('data-consent-src', source);
        video.api.setState('default');
      }
    });
  });
</script>

<H2 id="integration">Resource gating and API</H2>

<p>Author scripts as inert placeholders and omit iframe source attributes. Only the accepted service receives its resource URL. Do not use an executable script type or a live iframe source before consent: initialization cannot undo earlier execution or network requests.</p>

```html
<script type="text/plain" data-cookie-consent="measurement"
        data-consent-src="/measurement.js" nonce="csp-nonce"></script>
<script type="text/plain" data-cookie-consent="feature"
        data-consent-type="module" data-consent-src="/feature.mjs"></script>
<iframe title="Optional video" data-cookie-consent="video"
        data-consent-src="/video-player.html" loading="lazy"></iframe>
```

<p>Use programmatic configuration for revocation hooks or custom storage. The existing <code>cookieOrigins</code> field and category identifiers are preserved. The <code>other</code> category is optional; legacy optional <code>consent: true</code> values do not bypass choice.</p>

```ts
const root = df$('#privacy')[0];
const consent = df$.shadcn.cookieConsent.create(root, {
  revision: '2026-10',
  storageKey: 'site:privacy',
  cookieOrigins: [{
    id: 'measurement', name: 'Measurement', category: 'functional',
    description: 'Measures usage after your explicit permission.',
    cookies: [{ name: 'measurement', path: '/' }],
    onRevoke: () => measurementSdk.stop(),
  }],
});
consent.open();
consent.isServiceAccepted('measurement');
consent.getConsent();
df$(root).on('cookie-consent:change', event => {
  console.log(event.detail.state, event.detail.reason);
});
```

<p>Removing an executed script does not undo its effects. Supply service cleanup through <code>onRevoke</code> or handle withdrawal in your host application. Each script placeholder executes once; a regrant requires host SDK lifecycle handling or a reload. Iframe denial unloads the document. Cookie deletion needs the matching path and domain; third-party and HttpOnly cookies require browser/server handling.</p>

<p>Instance methods: <code>open</code>, <code>close</code>, <code>acceptAll</code>, <code>denyAll</code>, <code>save</code>, <code>acceptService</code>, <code>revokeService</code>, <code>getConsent</code>, <code>getDraft</code>, <code>isServiceAccepted</code>, <code>setLanguage</code>, <code>reset</code>, <code>updateTagsActivation</code>, and <code>destroy</code>. Use <code>resourceRoot</code> to isolate independent instances. Preserve stable host/service IDs and increase <code>revision</code> when purposes change.</p>

<StatesSection>
  <p>Named states: <code>default</code> closes, <code>open</code> shows the introduction, <code>preferences</code> shows categories, and <code>services</code> shows individual services. Drive them through <code>root.api.setState(name)</code>. Named states change presentation only and never grant consent.</p>

```states
| State | Type | Values | Default | Description |
| --- | --- | --- | --- | --- |
| `open` | `boolean` | `true`, `false` | `false` | The introduction: the explanation and three equal-weight actions. |
| `preferences` | `boolean` | `true`, `false` | `false` | The category choices (a draft until saved). |
| `services` | `boolean` | `true`, `false` | `false` | The individual services with their details. |
```

</StatesSection>
