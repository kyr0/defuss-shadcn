<H2>What is a component skill?</H2>

<p class="text-sm text-muted-foreground mb-5">A component skill is a Markdown file that documents the <strong>HTML pattern</strong> for a component — what elements to use, which attributes to set, what variants and sizes are available, and the ARIA requirements. It's the single source of truth for how to write the markup.</p>

<p class="text-sm text-muted-foreground mb-5">Component skills don't contain CSS or JavaScript code — those live in their own files alongside the skill. The skill focuses purely on the HTML structure and its configuration options.</p>

<CodeCard title="file location" lang="bash" mb="2.5rem">{"dist/components/{name}/\n├── component-skill.md   "}<Dim>{"← the skill file (HTML reference)"}</Dim>{"\n├── {name}.css            "}<Dim>{"← component stylesheet"}</Dim>{"\n└── {name}.js             "}<Dim>{"← interaction JS (if needed)"}</Dim></CodeCard>

<H2>The SKILL.md index</H2>

<p class="text-sm text-muted-foreground mb-5"><code>dist/SKILL.md</code> is the generated entry point of the whole system — integration instructions, the library's philosophy, a map of the <code>dist/</code> layout, and one index entry per component (its taxonomy type, why to use it, when to reach for it, which files ship it, and which states it supports). It is built on every build from <code>SKILL\_tpl.md</code> plus each skill's frontmatter, so it can never drift from the skills it indexes.</p>

<p class="text-sm text-muted-foreground mb-5"><strong>If you are an agent wiring this library into a project, point yourself at <a href="https://cdn.jsdelivr.net/gh/kyr0/defuss-shadcn@latest/dist/SKILL.md"><code>dist/SKILL.md</code></a> first</strong> — it tells you what to include, which skill to read next, and where the state screenshots live (<code>screenshots/\{light,dark\}/\{name\}-\{state\}.png</code> in the source repo), so you can look up exactly what an "open modal" or "collapsed sidebar" should look like before you build it.</p>

<H2>Skill file structure</H2>

<p class="text-sm text-muted-foreground mb-5">Every component skill opens with a YAML frontmatter block and then follows a consistent template with these sections in order:</p>

<div style="display:grid;grid-template-columns:auto 1fr;gap:0.5rem 1rem;margin-bottom:2.5rem;align-items:baseline;">
  <span style="font-weight:600;font-size:0.8125rem;">0. Frontmatter</span>
  <span class="text-sm text-muted-foreground">Machine-readable header (<code>name</code>, <code>type</code>, <code>why</code>, <code>when</code>, <code>where</code>, <code>supportedStates</code>) that <code>SKILL.md</code> is generated from — required on every skill and enforced by <code>verify</code>.</span>
  <span style="font-weight:600;font-size:0.8125rem;">1. Native basis</span>
  <span class="text-sm text-muted-foreground">Which HTML element or browser API the component builds on. Every component starts from native semantics.</span>
  <span style="font-weight:600;font-size:0.8125rem;">2. Native Web APIs</span>
  <span class="text-sm text-muted-foreground">Bulleted list of significant platform APIs used (Popover API, CSS Anchor Positioning, <code>&lt;dialog&gt;</code>, etc.) with MDN links.</span>
  <span style="font-weight:600;font-size:0.8125rem;">3. Structure</span>
  <span class="text-sm text-muted-foreground">Complete HTML markup showing the component's element hierarchy, class names, and required attributes.</span>
  <span style="font-weight:600;font-size:0.8125rem;">4. Variants</span>
  <span class="text-sm text-muted-foreground">Table of <code>data-variant</code> values with descriptions and example markup.</span>
  <span style="font-weight:600;font-size:0.8125rem;">5. Sizes</span>
  <span class="text-sm text-muted-foreground">Table of <code>data-size</code> values (if the component supports them).</span>
  <span style="font-weight:600;font-size:0.8125rem;">6. Accessibility</span>
  <span class="text-sm text-muted-foreground">Required ARIA attributes, keyboard interactions, and screen reader considerations.</span>
  <span style="font-weight:600;font-size:0.8125rem;">7. Notes</span>
  <span class="text-sm text-muted-foreground">Edge cases, composition tips, caveats, and integration notes.</span>
</div>

<h2 id="component-taxonomy" style="font-family:var(--font-display);font-size:1.375rem;font-weight:400;letter-spacing:-0.02em;margin:0 0 0.875rem;">Component taxonomy</h2>

<p class="text-sm text-muted-foreground mb-5">Every component is classified with exactly one type, expressed in three places that <code>verify</code> keeps in sync: the skill's <code>type:</code> frontmatter (source of truth), the sidebar badge, and the badge on the component's doc page. Classification never leaks into component names — <code>Button</code>, never <code>ButtonAtom</code>.</p>

<div style="display:grid;gap:0.5rem;margin-bottom:2.5rem;">
  <div class="flex items-center gap-2">
    <span class="type-badge" data-type="ATM" title="Atom">ATM</span>
    <span class="text-sm text-muted-foreground"><strong>Atom</strong> — contains no descendant components (any DOM inside, but no other component).</span>
  </div>
  <div class="flex items-center gap-2">
    <span class="type-badge" data-type="MOL" title="Molecule">MOL</span>

  </div>

    <span class="type-badge" data-type="ORG" title="Organism">ORG</span>
    <span class="text-sm text-muted-foreground"><strong>Organism</strong> — direct children are atoms and/or molecules, with ≥1 molecule.</span>

<H2>Using skills with AI assistants</H2>

<p class="text-sm text-muted-foreground mb-5">Component skills are designed to give AI assistants everything they need to generate correct, accessible markup in a single reference. Here's how to use them:</p>

<div style="display:grid;grid-template-columns:auto 1fr;gap:0.75rem 1.5rem;margin-bottom:1.5rem;align-items:baseline;">
  <span style="font-weight:600;font-size:0.8125rem;">Start at SKILL.md</span>
  <span class="text-sm text-muted-foreground">Give the agent <code>dist/SKILL.md</code> as its entry point: it explains integration and philosophy once, then points at the right component skill — the agent only reads the skills it actually needs.</span>
  <span style="font-weight:600;font-size:0.8125rem;">Copy &amp; paste</span>
  <span class="text-sm text-muted-foreground">Copy the skill file content into your AI chat alongside your request. The AI will use it as context to generate correct markup.</span>
  <span style="font-weight:600;font-size:0.8125rem;">File reference</span>
  <span class="text-sm text-muted-foreground">In tools that support file context (Copilot, Cursor, etc.), point the AI at <code>dist/components/\{name\}/component-skill.md</code>.</span>
  <span style="font-weight:600;font-size:0.8125rem;">Multiple skills</span>
  <span class="text-sm text-muted-foreground">For pages with multiple components, provide all relevant skill files. The AI will compose them correctly.</span>
</div>

<CodeCard title="example AI prompt" lang="markdown" mb="2.5rem">{"Using the defuss-shadcn component system, build a\nsettings page with:\n- A card containing a form with two text inputs\n- A destructive button to delete the account\n- A toast notification on save\n\nHere are the component skills:\n[paste card, form, input, button, and toast skills]"}</CodeCard>

<H2>Using skills as a human reference</H2>

<p class="text-sm text-muted-foreground mb-5">Even without AI, skill files serve as quick references. Need to know what variants a Badge supports? Open <code>component-skill.md</code> and check the variants table. Need the exact ARIA attributes for a Combobox? The accessibility section has them.</p>

<div style="display:grid;grid-template-columns:auto 1fr;gap:0.5rem 1rem;margin-bottom:2.5rem;align-items:baseline;">
  <span style="font-weight:600;font-size:0.8125rem;">Quick lookup</span>
  <span class="text-sm text-muted-foreground">Skill files are faster than searching through CSS for which <code>data-variant</code> values exist or scanning JS for keyboard bindings.</span>
  <span style="font-weight:600;font-size:0.8125rem;">Copy-paste HTML</span>
  <span class="text-sm text-muted-foreground">The Structure section gives you copy-paste-ready markup with all required attributes already in place.</span>
  <span style="font-weight:600;font-size:0.8125rem;">ARIA checklist</span>
  <span class="text-sm text-muted-foreground">The Accessibility section doubles as a checklist to verify your implementation covers all accessibility requirements.</span>
</div>
