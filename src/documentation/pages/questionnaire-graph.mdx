<PageHeader slug="questionnaire-graph" title="Flow Graph" component="questionnaire">
  Every questionnaire is a directed graph: steps are nodes, and each <code>data-goto</code>, rule and <code>data-next</code> is an edge. The controller walks it - and it can also check it before anyone fills it in, and draw it. <code>analyze(form)</code> runs on every form at load (a broken one gets <code>data-flow-invalid</code> and a console warning); <code>toDiagram(form)</code> turns the graph into an <a class="link" href="diagram.html">Illustrative Diagram</a> spec with the path taken so far marked, and <code>linkDiagram(form, figure)</code> keeps one in step with the form - both ways. <code>toMermaid(form)</code> exports the same graph as a <a class="link" href="mermaid.html">Mermaid</a> flowchart (live on the Mermaid page).
</PageHeader>

<H2 id="analyze">Checking a flow</H2>

<DocText><code>analyze(form)</code> returns <code>\{ ok, errors, warnings, nodes, edges \}</code>. <strong>Errors</strong>: an edge to a step that does not exist, a cycle (a questionnaire must end), a dead end (a step that leads nowhere and is no <code>data-end</code>), no end at all or none reachable, a rule or <code>data-depends-on</code> that reads a field no step asks. <strong>Warnings</strong>: steps no path reaches, and fields a rule reads that a path can arrive without - computed with <em>dominators</em>: a field is only guaranteed at a step when every path to it passes a step where the field is required.</DocText>

<H2 id="dominators">Why dominators</H2>

<DocText>A rule on step <em>S</em> that reads the answer <em>f</em> is only safe if every way to <em>S</em> asked <em>f</em> - otherwise some users reach <em>S</em> without it, the condition sees nothing, and the branch quietly goes the other way. A step <em>D</em> dominates <em>S</em> when every path from the start to <em>S</em> passes <em>D</em>; the fields that are required on <em>S</em>'s dominators are exactly the fields guaranteed at <em>S</em>. In the broken flow above, <code>coupon</code> is asked only on the B branch, so the rule on <code>details</code> gets a warning. In the onboarding flow the rule on <code>size</code> reads <code>size</code> itself - always safe.</DocText>
