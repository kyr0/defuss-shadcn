<PageHeader slug="state-api" title="State API" introStyle="max-width:38rem;">
  Interactive components don't just look stateful - they <em>declare</em> their states. Every component that ships a <code>.js</code> file exposes its states by name, so agents, tests, and your own code can drive and observe any documented state without knowing the implementation.
</PageHeader>

<H2>The contract</H2>

<p class="text-sm text-muted-foreground mb-5"> Each component instance binds a tiny API directly on the element. State lives <em>on the element</em> (never in module scope), so twenty components on one page can each hold a different state: </p>

<CodeCard title="the shape - any JS component" lang="javascript" mb="2.5rem">{"// set a declared state by name - throws on unknown names\nel.api.setState('open', { /* optional config */ });\n\n// read it back - always reflects the real UI\nel.api.getState(); // → { name: 'open', config: { ... } }"}</CodeCard>

<p class="text-sm text-muted-foreground mb-5"> Three guarantees, verified by <DocLink href="https://github.com/kyr0/defuss-shadcn/blob/main/scripts/verify.ts" target="_blank">the build's verifier</DocLink> for every component: </p>

<div class="grid grid-cols-auto gap-4 mb-10">
  <div style="border:1px solid var(--border);border-radius:var(--radius-xl);padding:1.25rem;">
    <p class="text-sm font-medium mb-2" style="margin-top:0;">Declared, not implied</p>
    <p class="text-sm text-muted-foreground" style="margin-bottom:0;"> Each component lists its states as names (<code>const dialogStates = ['default', 'open']</code>) - <code>default</code> first. Unknown names throw with the supported list. </p>
  </div>
  <div style="border:1px solid var(--border);border-radius:var(--radius-xl);padding:1.25rem;">
    <p class="text-sm font-medium mb-2" style="margin-top:0;">Honest reads</p>
    <p class="text-sm text-muted-foreground" style="margin-bottom:0;"> <code>getState()</code> reflects what the user sees: pressing Escape on an open dialog returns <code>default</code>, not the stale last <code>setState</code> value. </p>
  </div>
  <div style="border:1px solid var(--border);border-radius:var(--radius-xl);padding:1.25rem;">
    <p class="text-sm font-medium mb-2" style="margin-top:0;">Documented visually</p>
    <p class="text-sm text-muted-foreground" style="margin-bottom:0;"> Every state is a named entry in the component's skill (<code>## States</code>), a section on its doc page, and a real screenshot in both light and dark mode. </p>
  </div>
</div>

<H2>Discovering the states</H2>

<p class="text-sm text-muted-foreground mb-5"> Three places name the same list. The skill frontmatter is the machine-readable source - <code>dist/SKILL.md</code> indexes it, and every component's doc page shows the states with a live demo: </p>

<CodeCard title="dialog/component-skill.md" lang="markdown" mb="1.5rem">{"---\nname: Dialog\ntype: MOL\n...\nsupportedStates: default, open\n---\n\n## States\n- `default` - closed (authored initial state)\n- `open` - shown modally via showModal()\n\n```js\ndocument.querySelector('#confirm')\n  .api.setState('open');\n```"}</CodeCard>

<p class="text-sm text-muted-foreground mb-5"> The component scripts also register their states and a registry-level API on <code>globalThis.df$</code> - useful when you have no element handle yet: </p>

<CodeCard title="registry globals (set by each component .js)" lang="javascript" mb="2.5rem">{"globalThis.df$.shadcn.dialogStates;  // ['default', 'open']\n\n// registry form - element passed explicitly, same contract as el.api\nconst { dialogApi } = globalThis.df$;\ndialogApi.setState(document.querySelector('#confirm'), 'open');\ndialogApi.getState(document.querySelector('#confirm'));\n// → { name: 'open', config: {} }"}</CodeCard>

<H2>Why it exists</H2>

<p class="text-sm text-muted-foreground mb-5"> The <DocLink href="architecture.html">VAE page</DocLink> describes the proof loop: every declared state of every component must be visually verifiable - a screenshot per state per color scheme, driven through <code>api.setState()</code> by <code>scripts/create-screenshots.ts</code> - and asserted by an e2e test. That is only possible because the states are named, uniform, and callable from plain JavaScript, no matter what the component does internally. Your agents get the same handle: <a href="component-skills.html">the skills</a> name the states, the API drives them. </p>

<p class="text-sm text-muted-foreground mb-8"> See also: <DocLink href="how-to-use.html">How to Use</DocLink> (where the <code>.js</code> layer sits), <DocLink href="data-attribute-api.html">Data Attribute API</DocLink> (markup configuration, as opposed to runtime state). </p>
