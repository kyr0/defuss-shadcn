<PageHeader slug="state-api" title="State API" introStyle="max-width:38rem;">
  Interactive components don't just look stateful - they <em>declare</em> their states. Every component that ships a <code>.js</code> file exposes its states by name, so agents, tests, and your own code can drive and observe any documented state without knowing the implementation.
</PageHeader>

<H2>The contract</H2>

<p class="text-sm text-muted-foreground mb-5"> Each component instance binds a tiny API directly on the element. State lives <em>on the element</em> (never in module scope), so twenty components on one page can each hold a different state: </p>

<CodeWindow lang="javascript" title="the shape - any JS component" mb="2.5rem" code={"// the element - df$ selects it (get(0) = the node itself)\nconst el = df$('#confirm').get(0);\n\n// set a declared state by name - throws on unknown names\nel.api.setState('open', { /* optional config */ });\n\n// read it back - always reflects the real UI\nel.api.getState(); // → { name: 'open', config: { ... } }"} />

<p class="text-sm text-muted-foreground mb-5"> Three guarantees, verified by <DocLink href="https://github.com/kyr0/defuss-shadcn/blob/main/scripts/verify.ts" target="_blank">the build's verifier</DocLink> for every component: </p>

<div class="grid grid-cols-auto gap-4 mb-10">
  <div style="border:1px solid var(--border);border-radius:var(--radius-xl);padding:1.25rem;">
    <p class="text-sm font-medium mb-2" style="margin-top:0;">Declared, not implied</p>
    <p class="text-sm text-muted-foreground" style="margin-bottom:0;"> Each component lists its states as names (<code>const dialogStates = ['default', 'open']</code>) - <code>default</code> first. Unknown names throw with the supported list. </p>
  </div>
  <div style="border:1px solid var(--border);border-radius:var(--radius-xl);padding:1.25rem;">

    <p class="text-sm text-muted-foreground" style="margin-bottom:0;"> <code>getState()</code> reflects what the user sees: pressing Escape on an open dialog returns <code>default</code>, not the stale last <code>setState</code> value. </p>
  </div>
  <div style="border:1px solid var(--border);border-radius:var(--radius-xl);padding:1.25rem;">

<H2>Try it</H2>

<p class="text-sm text-muted-foreground mb-5"> The buttons below call <code>api.setState()</code> and print what <code>api.getState()</code> reads back. Closing the dialog with Escape or the backdrop flips the observed state to <code>default</code> on its own - the read always matches the UI. </p>

```html example label="Drive the dialog by name" schema="none" height="24" hint="The same API keyboard users, tests and agents use: the buttons call api.setState() and print what api.getState() reads back. Close the dialog with Escape, the backdrop or its button - the named state follows the UI, so the badge flips back to default on its own."
<div class="flex flex-wrap items-center gap-2">
  <button class="btn" type="button" id="sa-open">api.setState('open')</button>
  <button class="btn" data-variant="outline" type="button" id="sa-default">api.setState('default')</button>
  <output class="badge" data-variant="secondary" id="sa-out" aria-live="polite">default</output>
</div>
<dialog id="sa-dialog" class="dialog" aria-labelledby="sa-title">
  <div class="dialog-content">
    <div class="dialog-header">
      <h2 class="dialog-title" id="sa-title">Named state</h2>
      <p class="dialog-description">Opened via api.setState('open') - close it and watch the badge flip back to default.</p>
    </div>
    <div class="dialog-footer">
      <button class="btn" data-variant="outline" data-dialog-close>Close</button>
    </div>
  </div>
</dialog>
<script>
  document.addEventListener('DOMContentLoaded', () => {
    // df$ selects; dialog.js has bound dialog.api on the element
    const dialog = df$('#sa-dialog').get(0);
    const show = () => df$('#sa-out').text(dialog.api.getState().name);
    df$('#sa-open').on('click', () => { dialog.api.setState('open'); show(); });
    df$('#sa-default').on('click', () => { dialog.api.setState('default'); show(); });
    // Escape / backdrop / close button: the state follows the dialog
    df$(dialog).on('close', () => queueMicrotask(show));
  });
</script>
```

<H2>Discovering the states</H2>

<p class="text-sm text-muted-foreground mb-5"> Three places name the same list. The skill frontmatter is the machine-readable source - <code>dist/SKILL.md</code> indexes it, and every component's doc page shows the states with a live demo: </p>

<CodeWindow lang="markdown" title="dialog/component-skill.md" mb="1.5rem" code={"---\nname: Dialog\ntype: MOL\n...\nsupportedStates: default, open\n---\n\n## States\n- `default` - closed (authored initial state)\n- `open` - shown modally via showModal()\n\n```js\ndf$('#confirm').get(0).api.setState('open');\n```"} />

<p class="text-sm text-muted-foreground mb-5"> The component scripts also register their states and a registry-level API on <code>globalThis.df$</code> - useful when you have no element handle yet: </p>

<CodeWindow lang="javascript" title="registry globals (set by each component .js)" mb="2.5rem" code={"df$.shadcn.dialogStates;  // ['default', 'open']\n\n// registry form - element passed explicitly, same contract as el.api\nconst { dialogApi } = df$.shadcn;\nconst confirm = df$('#confirm').get(0);\ndialogApi.setState(confirm, 'open');\ndialogApi.getState(confirm);\n// → { name: 'open', config: {} }"} />

<H2>Why it exists</H2>

<p class="text-sm text-muted-foreground mb-5"> The <DocLink href="architecture.html">VAE page</DocLink> describes the proof loop: every declared state of every component must be visually verifiable - a screenshot per state per color scheme, driven through <code>api.setState()</code> by <code>scripts/create-screenshots.ts</code> - and asserted by an e2e test. That is only possible because the states are named, uniform, and callable from plain JavaScript, no matter what the component does internally. Your agents get the same handle: <a href="component-skills.html">the skills</a> name the states, the API drives them. </p>
