<h2 id="one-scale" class="h2-display">One scale, two vocabularies</h2>

<DocText>A numeric size is a quantity, not an index: <code>w-4</code> means four base units. Named properties select useful points on the same scale. The default <code>--size-base</code> reads the existing <code>--spacing</code> token, with <code>0.25rem</code> as its fallback. These are predictable design defaults, not a claim of universally optimal dimensions.</DocText>

<h2 id="density-is-not-resolution" class="h2-display">Density is not display resolution</h2>

<DocText>CSS pixels already abstract device pixels; <code>rem</code> follows the root font size. No device-pixel-ratio multiplier and no root-font reset are added. Layout density changes opted-in gaps, margins, padding and container gutters—not numeric widths, heights, icons or typography. <a href="https://www.w3.org/TR/css-values-4/" target="_blank" rel="noopener">CSS Values and Units</a></DocText>

<h2 id="toolbox" class="h2-display">The sizing toolbox</h2>

<DocText>Real UI mixes fixed and flexible sizes on one row: a <code>size-10 shrink-0</code> avatar square, a <code>flex-1 min-w-0</code> text column that absorbs the remaining width without widening the page, and a <code>shrink-0</code> action that keeps its own size. The same scale sizes icon boxes inside buttons — a <code>size-4</code> SVG lines up with the label's line height.</DocText>

<h2 id="targets" class="h2-display">Size the target, not only the icon</h2>

<DocText>WCAG 2.2 AA uses a <strong>24 × 24 CSS-pixel</strong> target-size criterion, with exceptions including sufficient spacing. The enhanced AAA criterion uses <strong>44 × 44 CSS pixels</strong>, also with exceptions. These concern the interactive target, not the visible icon. <a href="https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html" target="_blank" rel="noopener">WCAG 2.2: Target Size (Minimum), AA</a> · <a href="https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html" target="_blank" rel="noopener">WCAG 2.2: Target Size (Enhanced), AAA</a></DocText>

<DocText>Use 44px minimum dimensions as a starting point for touch-oriented controls; assess the actual clickable shape and surrounding targets. A minimum-size declaration alone does not certify WCAG conformance. Existing buttons are not silently resized by this module.</DocText>

```html
<button class="btn" type="button" aria-label="Add project"
  style="min-inline-size:44px;min-block-size:44px;">
  <svg class="size-4" viewBox="0 0 16 16" aria-hidden="true">
    <path d="M8 2v12M2 8h12" fill="none" stroke="currentColor"/>
  </svg>
</button>
```

<h2 id="install" class="h2-display">Install only what you use</h2>

```html
<link rel="stylesheet" href="../theme/utils/default-semantic-tokens.css">
<link rel="stylesheet" href="../theme/utils/sizing.css">
<link rel="stylesheet" href="../theme/utils/layout.css">
<link rel="stylesheet" href="../theme/utils/accessibility.css">
<!-- Load the component stylesheets you actually use next. -->
<link rel="stylesheet" href="../components/button/button.css">
```


<DocText>The optional modules live beside the theme assets so the existing copy build and CDN mirror work unchanged. They are not part of the replaceable semantic-token export. Both files declare <code>@layer components, utilities</code>; load them before component CSS so that order is established first. A later layer declaration cannot reorder layers that already exist. Normal unlayered application CSS overrides both.</DocText>

<h2 id="customize" class="h2-display">Override properties, not generated classes</h2>

```css
/* Global application CSS; do not edit a tweakcn export. */
:root {
  --size-base: 0.3rem;
  --layout-density: 1;
}

/* Local scale: redeclare aliases at this explicit boundary. */
.compact-panel {
  --size-base: 0.2rem;
}
```


```html
<section class="compact-panel" data-size-scope>
  <div class="w-16 h-8">Local scale</div>
  <div style="padding:var(--size-sm);">Named local size</div>
</section>
```


<DocText>Custom-property formulas resolve before inheritance. When a local <code>--size-base</code> changes, add <code>data-size-scope</code> on that element to recompute its named aliases. Numeric utilities use the base directly. Prefer custom properties or a small semantic rule to inventing unsupported class names.</DocText>
