<PageHeader slug="data-attribute-api" title="Data Attribute API" introStyle="max-width:38rem;">
  In React or Solid, you configure components with props. In defuss-shadcn, data attributes are your props. Every component uses a single CSS class to declare <em>what</em> it is, and <code>data-\*</code> attributes to declare <em>which version</em> - variant, size, orientation, and behavior.
</PageHeader>

<H2>Props → Data Attributes</H2>

<p class="text-sm text-muted-foreground mb-5">If you came from a component framework, this mapping should feel familiar.</p>

<div class="grid grid-cols-auto gap-4 mb-10">
  <CodeWindow lang="markup" title="React / Solid (props)" column code={"<Button\n  variant=\"destructive\"\n  size=\"lg\"\n>\n  Delete\n</Button>"} />
  <CodeWindow lang="markup" title="defuss-shadcn (data attributes)" column code={"<button class=\"btn\"\n  data-variant=\"destructive\"\n  data-size=\"lg\"\n>\n  Delete\n</button>"} />
</div>

<div class="sep" />

<H2>How it works</H2>

<p class="text-sm text-muted-foreground mb-5">Every component has exactly two layers in its markup: a class and its data attributes.</p>

<div style="display:grid;grid-template-columns:auto 1fr;gap:0.75rem 1.5rem;margin-bottom:1.5rem;align-items:baseline;">
  <code style="font-size:0.8125rem;font-weight:600;">class</code>
  <span class="text-sm text-muted-foreground">Identifies <strong>what</strong> the element is - <code>.btn</code>, <code>.badge</code>, <code>.card</code>, <code>.dialog</code>. One class per component. This is the base selector in CSS.</span>
  <code style="font-size:0.8125rem;font-weight:600;">data-variant</code>
  <span class="text-sm text-muted-foreground">Selects the visual style - <code>default</code>, <code>outline</code>, <code>ghost</code>, <code>destructive</code>, etc. Think of it as the component's "skin."</span>
  <code style="font-size:0.8125rem;font-weight:600;">data-size</code>
  <span class="text-sm text-muted-foreground">Selects the size - <code>sm</code>, <code>lg</code>, <code>icon</code>, etc. Controls height, padding, and font-size.</span>
  <code style="font-size:0.8125rem;font-weight:600;">data-\*</code>
  <span class="text-sm text-muted-foreground">Additional axes like <code>data-orientation</code>, <code>data-side</code>, <code>data-position</code> - each controls one independent dimension. Compose freely.</span>
</div>

<p class="text-sm text-muted-foreground mb-8">The CSS combines these with attribute selectors: <code>.btn\[data-variant="outline"\]</code>. No modifier classes, no BEM suffixes, no utility chains.</p>

<div class="sep" />

<H2>Why data attributes instead of modifier classes?</H2>

<p class="text-sm text-muted-foreground mb-5">Traditional systems like Bootstrap and BEM use modifier classes: <code>.btn-primary</code>, <code>.btn--lg</code>, <code>.btn-outline-danger</code>. Here's why we don't.</p>

<div class="grid grid-cols-auto gap-4 mb-10">
  <CodeWindow lang="html" title="Modifier classes" column code={"<button class=\"btn btn-destructive btn-lg\">\n  Delete\n</button>\n\n<style>\n  /* Conflicting specificity */\n  .btn-primary { ... }\n  .btn-lg { ... }\n  .btn-primary.btn-lg { ... }\n</style>"} />
  <CodeWindow lang="html" title="Data attributes" column code={"<button class=\"btn\"\n  data-variant=\"destructive\"\n  data-size=\"lg\">\n  Delete\n</button>\n\n<style>\n  /* Flat specificity - no combos needed */\n  .btn[data-variant=\"destructive\"] { ... }\n  .btn[data-size=\"lg\"] { ... }\n</style>"} />
</div>

<div style="display:grid;grid-template-columns:auto 1fr;gap:0.5rem 1rem;margin-bottom:2.5rem;align-items:baseline;">
  <span class="def-term">Flat specificity</span>
  <span class="text-sm text-muted-foreground">All variant/size selectors have equal weight. No specificity wars, no <code>!important</code>.</span>
  <span class="def-term">Independent axes</span>
  <span class="text-sm text-muted-foreground">Variant and size combine freely without needing combinatorial class names like <code>.btn-outline-lg</code>.</span>
  <span class="def-term">Uniform API</span>
  <span class="text-sm text-muted-foreground">Every component follows the same pattern. Learn it once, apply everywhere. Easy for AI to generate.</span>
  <span class="def-term">Clean class attribute</span>
  <span class="text-sm text-muted-foreground">The <code>class</code> attribute stays a single token - <code>class="btn"</code> - not a long chain of modifiers.</span>
</div>

<CodeWindow lang="html" title="trigger / close pattern" mb="1.5rem" code={"<!-- The trigger: its value is the ID of the target -->\n<button class=\"btn\" data-dialog-trigger=\"confirm\">\n  Open Dialog\n</button>\n\n<!-- The target: matched by ID -->\n<dialog id=\"confirm\" class=\"dialog\">\n  <div class=\"dialog-content\">\n    <p>Are you sure?</p>\n    <!-- The close: placed inside, closes the nearest parent -->\n    <button class=\"btn\" data-dialog-close>Cancel</button>\n  </div>\n</dialog>"} />

<H2>ARIA attributes as styling hooks</H2>

<p class="text-sm text-muted-foreground mb-5">Where the browser natively provides state APIs - like <code>aria-selected</code>, <code>aria-expanded</code>, or <code>disabled</code> - we style against those directly. No data attributes are needed because the browser already exposes the state.</p>

<CodeWindow lang="css" title="native state as CSS selectors" mb="1.5rem" code={"/* Tab is selected - use ARIA, not a data attribute */\n.tab-trigger[aria-selected=\"true\"] {\n  color: var(--foreground);\n  border-color: var(--primary);\n}\n\n/* Toggle is pressed - native ARIA attribute */\n.toggle[aria-pressed=\"true\"] {\n  background: var(--accent);\n}\n\n/* Button is disabled - native HTML attribute */\n.btn:disabled {\n  opacity: 0.5;\n  cursor: not-allowed;\n}"} />

<p class="text-sm text-muted-foreground mb-8"><strong>Rule of thumb:</strong> if the browser has a native attribute for a state (<code>disabled</code>, <code>aria-selected</code>, <code>aria-expanded</code>, <code>open</code>), we style against that. Data attributes are only used when no native equivalent exists. </p>
