  <section class="paper-abstract" aria-labelledby="pe-abstract">
    <h2 id="pe-abstract">Abstract</h2>
    <p>A component of defuss-shadcn is more than its stylesheet. It declares its states, documents them in a skill, types them in a schema, shows them on a page, tests them in a fixture and is photographed in each of them, light and dark. We draw these artifacts as an entity-relationship model; the verifier checks every relation in it on every build.</p>
  </section>

  <section class="paper-section" aria-labelledby="pe-s1">
    <h2 id="pe-s1"><span class="paper-num">1</span>Reading the model</h2>
    <p>Every component declares at least one state - <code>default</code> - and every state is captured twice, once per colour mode. A schema types the states of 68 of the 229 components: every interactive one but the chart - which the verifier lists as open debt - and nine native form and disclosure controls whose state is an attribute, such as an input or a checkbox.</p>
  </section>

  <section class="paper-section" aria-labelledby="pe-s2">
    <h2 id="pe-s2"><span class="paper-num">2</span>Who checks it</h2>
    <p>Each relation is a gate of the verifier: a skill without its states fails, a schema whose states differ from the page's table fails, a declared state without a screenshot or an end-to-end assertion fails. The diagram is the documentation of rules a program already enforces.</p>
  </section>
