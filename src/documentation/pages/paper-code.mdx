    <h2 id="pc-abstract">Abstract</h2>
    <p>The verifier measures the contrast of every theme's sidebar text. Its OKLCH conversion returned linear-light values and skipped the sRGB transfer, so a mid grey came out at 55 instead of 128 and every OKLCH contrast was measured too dark. The tests checked only black and white, where linear and gamma-encoded values agree. A probe found it; one function fixed it; a mid-tone test now pins it.</p>
  </section>

  <section class="paper-section" aria-labelledby="pc-s1">
    <h2 id="pc-s1"><span class="paper-num">1</span>The probe</h2>
    <p>Reference colours from CSS Color 4, converted by the verifier's parser:</p>
    <div class="mockup-code" data-chrome="mac" data-title="zsh - defuss-shadcn">
      <pre data-prefix="$"><code>bun tmp/oklch-probe.ts</code></pre>
      <pre><code>red   [ 255, 0, 0 ] want 255,0,0</code></pre>
      <pre><code>green [ 0, 255, 0 ] want 0,255,0</code></pre>
      <pre><code>blue  [ 0, 0, 255 ] want 0,0,255</code></pre>
      <pre data-tone="destructive" data-highlight><code>white [ 255, 255, 255 ] gray50 [ 55, 55, 55 ] want ~128</code></pre>
    </div>
    <p>The primaries match because 0 and 1 are the same in linear and gamma space; only the mid tone exposes the error.</p>
  </section>

  <section class="paper-section" aria-labelledby="pc-s2">
    <h2 id="pc-s2"><span class="paper-num">2</span>The fix</h2>
    <div class="mockup-code" data-numbers data-title="scripts/lib/contrast.ts">
      <pre><code>  const lin = [ /* LMS → linear sRGB */ ];</code></pre>
      <pre data-diff="remove"><code>  return lin.map((v) =&gt; Math.round(Math.min(1, Math.max(0, v)) * 255)) as RGB;</code></pre>
      <pre data-diff="add"><code>  const encode = (v: number) =&gt; (v &lt;= 0.0031308 ? 12.92 * v : 1.055 * v ** (1 / 2.4) - 0.055);</code></pre>
      <pre data-diff="add"><code>  return lin.map((v) =&gt; Math.round(Math.min(1, Math.max(0, <ins>encode</ins>(Math.min(1, Math.max(0, v))))) * 255)) as RGB;</code></pre>
    </div>
  </section>
