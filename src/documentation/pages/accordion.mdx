<PageHeader slug="accordion" title="Accordion" component="accordion">
  Collapsible content sections built on native <code>&lt;details&gt;</code> / <code>&lt;summary&gt;</code>. Multi-open needs zero JS. Single-open adds a small toggle handler.
</PageHeader>

<SkillPanel component="accordion">

  <SkillField label="Notes">
<SkillText dense>• <code>&lt;details&gt;/&lt;summary&gt;</code> is the most accessible accordion implementation - it works with zero JS and zero ARIA</SkillText>
  <SkillText dense>• For single-open behavior, the <code>toggle</code> event on <code>&lt;details&gt;</code> fires after the state changes</SkillText>
  <SkillText dense>• The <code>open</code> attribute is the source of truth for whether an item is expanded</SkillText>
  <SkillText dense>• Avoid nesting accordions - use a flat list with clear headings instead</SkillText>
  <SkillText dense>• A non-collapsible single accordion never closes its last open item - the attempt is denied in the cancellable <code>beforetoggle</code> event (<code>preventDefault()</code>), so the click is a silent no-op; reopening in <code>toggle</code> would flicker</SkillText>
  <SkillText dense>• The chevron rotation relies on <code>details\[open\] &gt;</code> selector - this is pure CSS</SkillText>
  <SkillText dense>• Content height animation uses <code>::details-content</code> pseudo-element with <code>block-size</code> transition and <code>@starting-style</code> for the enter animation - fully CSS-only, no JS measurement needed</SkillText>
  <SkillText dense>• Set <code>data-type="single"</code> for accordion behavior (only one open); omit for disclosure list (any number open)</SkillText>
  <p class="text-muted-foreground m-0">• Set <code>data-collapsible</code> alongside <code>data-type="single"</code> to allow all items to be closed</p>
  </SkillField>
</SkillPanel>
