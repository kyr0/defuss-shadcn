<h2 id="spacing-scale" style="font-family:var(--font-display);font-size:1.375rem;font-weight:400;letter-spacing:-0.02em;margin:0 0 0.875rem;">Spacing on the same base</h2>

<DocText>Gaps, padding and margins use <code>n × --size-base × --layout-density</code>. Density is 1 by default. <code>gap-4</code> therefore matches <code>1rem</code> at the default base; <code>w-4</code> remains geometric when density changes. The <code>px</code> suffix always means one CSS pixel and is not density-scaled. Below, the three everyday jobs of spacing: <code>gap-2</code> between related actions, <code>gap-6</code> between independent cards, <code>p-6</code> inside a card.</DocText>

<h2 id="box-model" style="font-family:var(--font-display);font-size:1.375rem;font-weight:400;letter-spacing:-0.02em;margin:0 0 0.875rem;">The box model, labeled</h2>

<DocText>Every spacing utility addresses one zone of the box model: <code>m-\*</code> works outside the border (against siblings), <code>p-\*</code> inside it (against content). The physical sides (<code>t/r/b/l</code>) never move; the logical sides (<code>s/e</code>) follow the writing direction. The diagram uses <em>ordinary CSS colors</em> to make the zones visible — the classes label what each zone is.</DocText>

<h2 id="gap-axes" style="font-family:var(--font-display);font-size:1.375rem;font-weight:400;letter-spacing:-0.02em;margin:0 0 0.875rem;">Gap axes</h2>

<DocText><code>gap-x-\*</code> sets <code>column-gap</code>, <code>gap-y-\*</code> sets <code>row-gap</code> — the two axes are independent. A calendar makes that tangible: days of a week sit <code>gap-x-3</code> apart while the weeks stack tightly at <code>gap-y-1</code>.</DocText>

<h2 id="padding" style="font-family:var(--font-display);font-size:1.375rem;font-weight:400;letter-spacing:-0.02em;margin:0 0 0.875rem;">Padding families</h2>

<DocText>Padding shares the numeric scale with gap. <code>p-\*</code> pads all four sides; <code>px-\*</code> and <code>py-\*</code> pad the inline and block axes independently — the recipe for chips, badges and inputs; a single-side helper like <code>pt-\*</code> adds space in one direction, useful for optical alignment against a divider or media edge. The dashed outline marks the box edge: the band between it and the filled content is the padding.</DocText>

<h2 id="margins" style="font-family:var(--font-display);font-size:1.375rem;font-weight:400;letter-spacing:-0.02em;margin:0 0 0.875rem;">Centering and pushing with margins</h2>

<DocText>Automatic margins absorb spare space. <code>mx-auto</code> on a fixed-width box centers it in its container — the classic content column. <code>ms-auto</code> on one flex item pushes it, and everything after it, to the inline end — the standard right-aligned toolbar action. Negative margins and margin-based <code>space-x/y</code> shortcuts are intentionally omitted.</DocText>

<h2 id="logical" style="font-family:var(--font-display);font-size:1.375rem;font-weight:400;letter-spacing:-0.02em;margin:0 0 0.875rem;">Physical vs logical sides</h2>

<DocText>The axis families already follow the writing mode — <code>px-\*</code> is <code>padding-inline</code>, <code>py-\*</code> is <code>padding-block</code>. For single sides there are two families: physical <code>pt/pr/pb/pl-\*</code> always hit the same physical edge, while logical <code>ps/pe-\*</code> follow inline-start and inline-end. The same classes render below in <code>dir="ltr"</code> and in <code>dir="rtl"</code>: the logical box mirrors with the direction, the physical box does not move. The filled band is the content box; the empty bands are the padding.</DocText>

<h2 id="overrides" style="font-family:var(--font-display);font-size:1.375rem;font-weight:400;letter-spacing:-0.02em;margin:0 0 0.875rem;">Custom gaps and cascade</h2>

<Demo>
  <DemoCode>{"<div class=\"stack\" style=\"--layout-gap:clamp(1rem, 2vw, 2rem);\">\n  <p>First block</p>\n  <p>Second block</p>\n</div>"}</DemoCode>
</Demo>

<DocText>A <code>--layout-gap</code> override configures a layout primitive. An explicit <code>gap-\*</code> helper overrides that primitive default. To override a helper, use normal unlayered application CSS. Avoid conflicting helpers; class-attribute order does not determine CSS precedence. Existing documentation helpers are unlayered and will win unless removed or isolated.</DocText>
