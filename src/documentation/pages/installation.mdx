<PageHeader slug="installation" title="Installation">
  Each component is a self-contained folder with a static component skill, a stylesheet, and a JavaScript file if needed. Two ways in: the jsDelivr CDN for plain HTML (no build step), or npm for projects that already have a package manager and bundler.
</PageHeader>

<h2 style="font-family:var(--font-display);font-size:1.5rem;font-weight:400;letter-spacing:-0.02em;margin:0 0 1rem;">Quick start</h2>

<p class="text-sm text-muted-foreground mb-6">All files are served via <DocLink href="https://www.jsdelivr.com" target="_blank">jsDelivr</DocLink> CDN directly from the GitHub repo. No download or install required - just reference the URLs in your HTML.</p>

    <p class="text-sm text-muted-foreground mt-2">Two delivery modes, one implementation: <strong>load core plus the components you use, or load all alone</strong> - both include the <code>df$</code> runtime (defuss-query + defuss-morph) through core; documentation code is separate, and there is no framework or jQuery dependency. <code>all.css</code> / <code>all.js</code> bundle the core runtime plus every component (this documentation site loads exactly these two files). Prefer a smaller payload? Load <code>core.js</code> once, then pick per-component <code>.css</code> + <code>.js</code> files from <code>components/\{name\}/</code> - a component script without core fails fast with one actionable load-order error. In between, a <DocLink href="bundles.html">section bundle</DocLink> loads one sidebar section at a time - the forms, the overlays, the website blocks - and every section also comes as a ZIP to vendor.</p>

<div style="margin-top:3rem;padding-top:2rem;border-top:1px solid var(--border);">
  <h2 style="font-family:var(--font-display);font-size:1.5rem;font-weight:400;letter-spacing:-0.02em;margin:0 0 0.75rem;">With a package manager</h2>
  <p class="text-sm text-muted-foreground mb-3">In a project that already has a package manager and a bundler (Vite, webpack, Rollup, Parcel, esbuild, Bun), install the package and import the same files in the same order - side-effect imports, once, in the app entry. The package ships plain CSS and ES modules; the bundler only resolves the paths.</p>
  <Terminal commands={"npm install defuss-shadcn   # or: bun add / pnpm add / yarn add defuss-shadcn"} />
  <CodeWindow lang="javascript" title="main.js" code={"// everything: tokens + utilities → all component CSS → runtime + all behavior\nimport 'defuss-shadcn/dist/components/core.css';\nimport 'defuss-shadcn/dist/components/all.css';\nimport 'defuss-shadcn/dist/components/all.js';\n\n// ...or only what you need (core.js MUST precede every component .js)\nimport 'defuss-shadcn/dist/components/core.css';\nimport 'defuss-shadcn/dist/components/dialog/dialog.css';\nimport 'defuss-shadcn/dist/components/core.js';\nimport 'defuss-shadcn/dist/components/dialog/dialog.js';"} />
  <p class="text-sm text-muted-foreground mt-2">Icons and charts stay separate packages: <code>npm install lucide</code> (then <code>createIcons(&#123; icons &#125;)</code>) for <code>&lt;i data-lucide&gt;</code>, and <code>npm install echarts</code> assigned to <code>globalThis.echarts</code> before a chart mounts. For AI agents, the package's <code>skills/defuss-shadcn/SKILL.md</code> condenses both install paths, the rules, and an index of every component skill and documentation page - install it into your coding agent with one command (see <DocLink href="vibe-coding.html#install-as-an-ai-agent-skill">Vibe Coding / Agentic Engineering</DocLink>).</p>

<div style="margin-top:3rem;padding-top:2rem;border-top:1px solid var(--border);">
  <h2 style="font-family:var(--font-display);font-size:1.5rem;font-weight:400;letter-spacing:-0.02em;margin:0 0 0.75rem;">Minified builds &amp; source maps</h2>
  <p class="text-sm text-muted-foreground mb-3">Every component also ships minified twins, generated at build time with <DocLink href="https://oxc.rs" target="_blank">oxc-minify</DocLink> (JS) and <DocLink href="https://lightningcss.dev" target="_blank">Lightning CSS</DocLink> (CSS). Swap the extension to <code>.min.css</code> / <code>.min.js</code> in any URL:</p>
  <CodeWindow lang="html" title="index.html · head" code={"<link rel=\"stylesheet\" href=\"https://cdn.jsdelivr.net/gh/kyr0/defuss-shadcn@latest/dist/components/dialog/dialog.min.css\">\n<script type=\"module\" src=\"https://cdn.jsdelivr.net/gh/kyr0/defuss-shadcn@latest/dist/components/dialog/dialog.min.js\"></script>"} />
  <p class="text-sm text-muted-foreground mt-2">Minification changes no behavior - the State API (<code>el.api.setState()</code>), globals and <code>data-\*</code> attributes work identically. Debugging stays intact: <code>dialog.js.map</code> maps the readable file back to its source and <code>dialog.min.js.map</code> maps the minified file through it; devtools pick both up automatically via <code>sourceMappingURL</code>, so you can set breakpoints in the original source even when loading the <code>.min.js</code>.</p>
  <p class="text-sm text-muted-foreground" style="margin-top:0.75rem;">The bundle ships the same way: <code>all.min.css</code> (+ <code>all.min.css.map</code>) and <code>all.min.js</code> (+ <code>all.min.js.map</code>) are the minified twins of <code>all.css</code> / <code>all.js</code> - swap them in by URL alone:</p>
  <CodeWindow lang="html" title="index.html · head" code={"<link rel=\"stylesheet\" href=\"https://cdn.jsdelivr.net/gh/kyr0/defuss-shadcn@latest/dist/components/all.min.css\">\n<script type=\"module\" src=\"https://cdn.jsdelivr.net/gh/kyr0/defuss-shadcn@latest/dist/components/all.min.js\"></script>"} />
  <p class="text-sm text-muted-foreground" style="margin-top:0.75rem;">Readable and minified files ship from the same source per release, so you can mix them freely - minified in production, readable while developing - and switch back by URL alone.</p>
