<h2 id="small-surface" style="font-family:var(--font-display);font-size:1.375rem;font-weight:400;letter-spacing:-0.02em;margin:0 0 0.875rem;">A small surface over native layout</h2>

<DocText>Use short, familiar classes for common operations; keep configuration properties descriptive. <code>flex</code> selects Flexbox and <code>grid</code> selects Grid. Neither silently chooses a gap, wrapping or columns. More opinionated composition is explicit.</DocText>

<h2 id="intrinsic" style="font-family:var(--font-display);font-size:1.375rem;font-weight:400;letter-spacing:-0.02em;margin:0 0 0.875rem;">Let available space do the work</h2>

<DocText>Use wrapping Flexbox for one-dimensional content and an intrinsic Grid for equal-width cards — the two halves of the composition demo above, which reacts when you resize it with the width toolbar. A grid can adapt inside a sidebar, dialog or full page without viewport breakpoints. Use container queries only when the structure must change.</DocText>

<h2 id="ownership" style="font-family:var(--font-display);font-size:1.375rem;font-weight:400;letter-spacing:-0.02em;margin:0 0 0.875rem;">Each primitive owns its parameters</h2>

<div style="overflow-x:auto;margin-bottom:1.5rem;">
  <table class="table" data-variant="simple">
    <thead>
      <tr>
        <th scope="col">Property</th>
        <th scope="col">Owner / default</th>
      </tr>
    </thead>
    <tbody>
      <tr>
        <td>
          <code>--layout-gap</code>
        </td>
        <td>Flex/grid/stack/center instance; resets at each nested root.</td>
      </tr>
      <tr>
        <td>
          <code>--layout-min</code>
        </td>
        <td>Grid instance; 16rem preferred auto-fit track minimum.</td>
      </tr>
      <tr>
        <td>
          <code>--layout-max</code>
        </td>
        <td>Container instance; 80rem outer maximum.</td>
      </tr>
      <tr>
        <td>
          <code>--layout-gutter</code>
        </td>
        <td>Container instance; four density-adjusted base units.</td>
      </tr>
    </tbody>
  </table>
</div>

<DocText>An outer grid’s track minimum must not accidentally configure an inner grid. Defaults are declared on each owning root; override that root with inline properties or unlayered application CSS. An explicit helper such as <code>gap-2</code> takes precedence over a primitive’s default gap.</DocText>

<h2 id="compatibility" style="font-family:var(--font-display);font-size:1.375rem;font-weight:400;letter-spacing:-0.02em;margin:0 0 0.875rem;">Familiar names, not a Tailwind compiler</h2>

<DocText>Numeric sizing, spacing, alignment, flex and fixed-grid names follow familiar Tailwind conventions at the default scale. <code>stack</code>, <code>center</code>, <code>query</code>, <code>grid-cols-auto</code> and the centered/guttered <code>container</code> are deliberate extensions. There are no arbitrary-value brackets, generated breakpoint prefixes, class scanning or runtime layout scripts. Use ordinary CSS for exceptional layouts.</DocText>

<DocText>Generic names can collide with other utility libraries. This module is optional; layers control precedence, not selector isolation. Documentation previews use separate documents so the legacy, unlayered docs utilities cannot mask the public CSS.</DocText>

<h2 id="semantics" style="font-family:var(--font-display);font-size:1.375rem;font-weight:400;letter-spacing:-0.02em;margin:0 0 0.875rem;">Keep semantics and reading order</h2>

<DocText>CSS Grid does not imply an ARIA grid widget. Preserve meaningful DOM order; no dense placement or visual-reordering helpers are shipped. Display helpers leave native hidden elements, until-found content, closed dialogs and closed popovers under native control. Long content still needs an explicit wrapping or scrolling policy; the module does not hide overflow.</DocText>
