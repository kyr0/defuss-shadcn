<PageHeader slug="image-gallery" title="Image Gallery" component="image">
  A composition pattern on top of the Image component: a crossfading, auto-advancing gallery where each slide declares its own dwell time in markup (<code>data-duration</code>) and a small defuss-query controller owns selection, state attributes, and the timer - no raw <code>querySelector</code>/<code>classList</code> anywhere.

<script type="module">
  // all.js (df$) is injected into the sandbox as a classic script at end of
  // body; module scripts run after parsing, so df$ is already live here at
  // the top level. EVERY DOM touch goes through defuss-query - the point of
  // the demo: no querySelector, no classList, no setAttribute.
  const track = df$('#igal').find('.image-gallery-track');
  const slides = track.children('.igal-slide'); // snapshot selection; .length is fine to read
  const counter = df$('#igal-counter');
  const playBtn = df$('#igal-play');
  const dwellInput = df$('#igal-dwell');

  let index = 0;
  let playing = true;
  let timer = 0; // stored timeout id - cleared and re-armed on every nav, pause, or config change

  // dwell of slide i: its own data-duration, else the configured default
  const dwellFor = (i) => {
    const own = Number(slides.eq(i).data('duration'));
    const fallback = Number(dwellInput.val());
    return own > 0 ? own : fallback > 0 ? fallback : 4000;
  };

  function render(next) {
    index = ((next % slides.length) + slides.length) % slides.length; // wrap around both ways
    slides.attr('data-active', null); // null REMOVES the attribute…
    slides.eq(index).attr('data-active', ''); // …and the CSS crossfade keys on it
    counter.text(index + 1 + ' / ' + slides.length);
  }

  function schedule() {
    clearTimeout(timer);
    if (!playing) return; // pausing is just clearing the pending advance
    timer = setTimeout(() => {
      render(index + 1);
      schedule(); // the next slide waits its own dwell - no fixed interval
    }, dwellFor(index));
  }

  df$('#igal-prev').on('click', () => { render(index - 1); schedule(); });
  df$('#igal-next').on('click', () => { render(index + 1); schedule(); });
  playBtn.on('click', () => {
    playing = !playing;
    playBtn.text(playing ? 'Pause' : 'Play').attr('aria-pressed', String(playing));
    schedule();
  });
  // editing the fallback re-arms the CURRENT slide when it has no own dwell
  dwellInput.on('input', () => schedule());

  schedule(); // start auto-sliding
</script>
```

<p class="text-sm text-muted-foreground m-0 mb-3">The pattern: <code>df$</code> (defuss-query) drives every DOM touch - selection (<code>find</code> / <code>children</code> / <code>eq</code>), attribute reads and writes (<code>data</code> / <code>attr</code>), label text (<code>text</code>), control values (<code>val</code>) and events (<code>on</code>) - while the crossfade itself is pure CSS keyed on the <code>data-active</code> attribute. Auto-advance is one re-armed <code>setTimeout</code> instead of a fixed interval: each slide's dwell is its own <code>data-duration</code>, falling back to the "Default dwell" field, and every manual navigation, pause, or config edit clears and re-arms the timer - user control always wins over the schedule.</p>
