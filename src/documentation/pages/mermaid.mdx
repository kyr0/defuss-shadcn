<PageHeader slug="mermaid" title="Mermaid" component="mermaid">
  Diagrams as text. Write Mermaid's own syntax in a <code>&lt;pre class="mermaid"&gt;</code> inside a <code>.mermaid-diagram</code> figure; the official Mermaid renderer turns it into an SVG in your theme's colors. The component ships no Mermaid code - the first diagram on a page loads the pinned official build once, a page without one never does. Without JavaScript the source reads as a code block.
</PageHeader>

```html example label="Added at runtime" hint="Diagrams inserted later - SPA navigation, streamed content, a click - render on their own: a MutationObserver finds them. No init call."
<button class="btn" data-variant="outline" id="mm-add">Add a diagram</button>
<div id="mm-host" class="stack gap-4 mt-4"></div>
<script>
  let n = 0;
  document.getElementById('mm-add').addEventListener('click', () => {
    n++;
    const fig = document.createElement('figure');
    fig.className = 'mermaid-diagram';
    fig.setAttribute('aria-label', 'Diagram ' + n);
    const pre = document.createElement('pre');
    pre.className = 'mermaid';
    pre.textContent = 'flowchart LR\n  Click' + n + '[click ' + n + '] --> Diagram' + n + '[diagram ' + n + ']';
    fig.append(pre);
    document.getElementById('mm-host').append(fig);
  });
</script>
```

<h2 id="in-docs" class="h2-display">In the docs: a fence</h2>

<DocText>In these docs (MDX) and in <code>ARCH.md</code>, a <code>mermaid</code> code fence becomes the component - the same figure, rendered by the same runtime. <code>label="…"</code> names it, <code>caption="…"</code> adds a figcaption. The <DocLink href="architecture.html">Verified Agentic Engineering</DocLink> proof loop and the <DocLink href="component-skills.html">Component Skills</DocLink> build diagram are written this way.</DocText>

```mermaid label="From fence to SVG" caption="One content primitive: text in the source, SVG in the browser."
flowchart LR
    Fence["mermaid fence<br/>(MDX or ARCH.md)"] --> Figure["figure.mermaid-diagram<br/>pre.mermaid"]
    Figure --> Static["static HTML:<br/>readable source"]
    Figure --> Runtime["mermaid.js<br/>+ design tokens"]
    Runtime --> SVG["themed SVG"]
```

<StatesSection>
  <p class="text-sm text-muted-foreground m-0 mb-3">Named states via the shared State API, bound on each figure:</p>
  <ul class="text-sm text-muted-foreground m-0 mb-3 ps-5">
    <li><code>default</code> - the source as text (not rendered yet, or reset)</li>
    <li><code>rendered</code> - the SVG, rendered from the source (setState re-renders)</li>
    <li><code>error</code> - the source plus the error message (<code>config.message</code>)</li>
  </ul>
  <p class="text-sm text-muted-foreground">The first example carries <code>data-state-demo</code>; <code>bun run screenshots</code> drives it via <code>el.api.setState(name)</code> and captures <code>screenshots/\{mode\}/mermaid-\{state\}.png</code>.</p>

Machine contract - verified against <a href="../schemas/mermaid.schema.json"><code>mermaid.schema.json</code></a> by <code>bun run verify</code>:

```states
| State | Type | Values | Default | Description |
| --- | --- | --- | --- | --- |
| `rendered` | `boolean` | `true`, `false` | `true` | The SVG is shown (unchecking returns to the source text via `setState('default')`). |
| `error` | `boolean` | `true`, `false` | `false` | The error state: the source plus an `output role="alert"` message. |
```
