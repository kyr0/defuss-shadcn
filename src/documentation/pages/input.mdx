```html example label="Readonly" hint="Non-editable value the user can still select and copy - so it gets a copy button: a trailing .input-group-button writes the value with navigator.clipboard and confirms with a check for 1.5 s. If the clipboard is blocked (e.g. a sandboxed frame), it selects the text instead so Ctrl/⌘+C works." height="11"
<label class="label" for="api-key">API Key</label>
<div class="input-group" style="max-width:24rem;">
  <input data-example-root class="input" type="text" id="api-key" readonly value="sk-1234567890abcdef" aria-describedby="api-key-desc" />
  <button type="button" class="input-group-button" id="api-key-copy" aria-label="Copy API key">
    <svg data-icon="copy" aria-hidden="true" width="16" height="16" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round"><rect width="14" height="14" x="8" y="8" rx="2"/><path d="M4 16c-1.1 0-2-.9-2-2V4c0-1.1.9-2 2-2h10c1.1 0 2 .9 2 2"/></svg>
    <svg data-icon="done" hidden aria-hidden="true" width="16" height="16" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round"><path d="M20 6 9 17l-5-5"/></svg>
  </button>
</div>
<p class="field-description" id="api-key-desc">Your API key is read-only.</p>
<script>
  const key = document.getElementById('api-key');
  const copy = document.getElementById('api-key-copy');
  const done = (label) => {
    copy.setAttribute('aria-label', label);
    copy.querySelector('[data-icon="copy"]').toggleAttribute('hidden', true);
    copy.querySelector('[data-icon="done"]').toggleAttribute('hidden', false);
    setTimeout(() => {
      copy.setAttribute('aria-label', 'Copy API key');
      copy.querySelector('[data-icon="copy"]').toggleAttribute('hidden', false);
      copy.querySelector('[data-icon="done"]').toggleAttribute('hidden', true);
    }, 1500);
  };
  copy.addEventListener('click', async () => {
    try {
      await navigator.clipboard.writeText(key.value);
      done('Copied');
    } catch {
      key.select(); // clipboard blocked: leave it selected for Ctrl/⌘+C
      done('Selected - press Ctrl+C to copy');
    }
  });
</script>

```html example label="Form composition" hint="data-validate=&quot;submit&quot; on the form: the browser still checks required and the email format, but a field only turns red once someone tries to submit - leaving a half-typed address is not an error. Two listeners stamp data-submitted on the attempt (invalid fires when the browser blocks it, submit when it passes); reset clears it. Without data-validate, a field inside a form turns red as soon as it is left with an invalid value." height="23"
<form id="compose-form" data-validate="submit" style="max-width:24rem;display:flex;flex-direction:column;gap:1.25rem;">
  <div>
    <label class="label" for="f-name">Name</label>
    <input class="input" type="text" id="f-name" required placeholder="Jane Doe" />
  </div>
  <div>
    <label class="label" for="f-email">Email</label>
    <input data-example-root class="input" type="email" id="f-email" required placeholder="jane@example.com" aria-describedby="f-email-desc" />
    <p class="field-description" id="f-email-desc">We'll never share your email with anyone.</p>
  </div>
  <div>
    <label class="label" for="f-bio">Bio</label>
    <textarea class="input" id="f-bio" placeholder="Tell us about yourself..."></textarea>
  </div>
  <div style="display:flex;gap:0.5rem;justify-content:flex-end;">
    <button class="btn" data-variant="outline" type="reset">Cancel</button>
    <button class="btn" data-variant="default" type="submit">Submit</button>
  </div>
</form>
<script>
  const compose = document.getElementById('compose-form');
  const attempted = () => compose.toggleAttribute('data-submitted', true);
  compose.addEventListener('invalid', attempted, true); // blocked by the browser's checks
  compose.addEventListener('submit', (e) => { attempted(); e.preventDefault(); });
  compose.addEventListener('reset', () => compose.removeAttribute('data-submitted'));
</script>
```

```html example label="Custom validation" hint="Your rule, your message, your moment. novalidate turns off the browser's bubbles; the page checks on submit - a username already taken, an invite code in a set shape, two passwords that must agree - and marks each failing field with aria-invalid, fills its .field-error and sets setCustomValidity (so :invalid and form.checkValidity() agree). Focus moves to the first problem. After that first attempt, each field re-checks as it is edited, so an error clears the moment it is fixed. Try: admin / abc / two different passwords." height="34"
<form id="signup" data-validate="submit" novalidate style="max-width:24rem;display:flex;flex-direction:column;gap:1.25rem;">
  <div>
    <label class="label" for="su-user">Username</label>
    <input class="input" type="text" id="su-user" name="username" autocomplete="username" aria-describedby="su-user-err" />
    <p class="field-error" id="su-user-err" hidden></p>
  </div>
  <div>
    <label class="label" for="su-code">Invite code</label>
    <input class="input" type="text" id="su-code" name="code" placeholder="ABC-1234" autocomplete="off" aria-describedby="su-code-hint su-code-err" />
    <p class="field-description" id="su-code-hint">Three letters, a dash, four digits.</p>
    <p class="field-error" id="su-code-err" hidden></p>
  </div>
  <div>
    <label class="label" for="su-pw">Password</label>
    <input class="input" type="password" id="su-pw" name="password" autocomplete="new-password" aria-describedby="su-pw-err" />
    <p class="field-error" id="su-pw-err" hidden></p>
  </div>
  <div>
    <label class="label" for="su-pw2">Repeat password</label>
    <input class="input" type="password" id="su-pw2" name="password2" autocomplete="new-password" aria-describedby="su-pw2-err" />
    <p class="field-error" id="su-pw2-err" hidden></p>
  </div>
  <div style="display:flex;gap:0.75rem;align-items:center;justify-content:flex-end;">
    <output id="su-done" class="text-sm text-muted-foreground"></output>
    <button class="btn" data-variant="default" type="submit">Create account</button>
  </div>
</form>
<script>
  const signup = document.getElementById('signup');
  const taken = new Set(['admin', 'root', 'john']);
  // one rule per field: return the message, or '' when the value is fine
  const rules = {
    'su-user': (v) =>
      !v ? 'Choose a username.'
      : !/^[a-z0-9_]{3,16}$/.test(v) ? 'Use 3-16 lowercase letters, digits or _.'
      : taken.has(v) ? 'That username is already taken.' : '',
    'su-code': (v) => (/^[A-Z]{3}-\d{4}$/.test(v) ? '' : 'Codes look like ABC-1234.'),
    'su-pw': (v) => (v.length >= 8 ? '' : 'Use at least 8 characters.'),
    'su-pw2': (v) => (v && v === signup.elements.password.value ? '' : "The passwords don't match."),
  };
  const check = (field) => {
    const message = rules[field.id](field.value.trim());
    field.setCustomValidity(message);
    if (message) field.setAttribute('aria-invalid', 'true');
    else field.removeAttribute('aria-invalid');
    const error = document.getElementById(field.id + '-err');
    error.textContent = message;
    error.hidden = !message;
    return !message;
  };
  const fields = Object.keys(rules).map((id) => document.getElementById(id));
  signup.addEventListener('submit', (e) => {
    e.preventDefault();
    signup.toggleAttribute('data-submitted', true);
    const failing = fields.filter((f) => !check(f));
    document.getElementById('su-done').value = failing.length ? '' : 'Account created.';
    failing[0]?.focus();
  });
  // after the first attempt, re-check while editing so fixed errors clear at once
  signup.addEventListener('input', (e) => {
    if (!signup.hasAttribute('data-submitted') || !(e.target.id in rules)) return;
    check(e.target);
    if (e.target.id === 'su-pw' && signup.elements.password2.value) check(signup.elements.password2);
  });
</script>
```

## States

Machine contract: the table below is verified against <a class="link" href="../schemas/input.schema.json"><code>input.schema.json</code></a> by <code>bun run verify</code> - state names, types, enum values and defaults must match in both directions. The CodeExample State tabs render their controls from exactly these rows (hint <code>editor</code> hints included), and state values observed from the live DOM win over schema defaults.

```states
| State | Type | Values | Default | Description |
| --- | --- | --- | --- | --- |
| `value` | `string` | — | `"Hello world"` | Current field value. Examples may set another value - the panel observes the DOM first. |
| `disabled` | `boolean` | `true`, `false` | `false` | Disables interaction (native `disabled` property). |
| `readonly` | `boolean` | `true`, `false` | `false` | Read-only value, selectable/copyable (`readonly` attribute; muted styling). |
| `required` | `boolean` | `true`, `false` | `false` | Marks the field required (`required` attribute; the adjacent `.label` renders its star automatically). |
| `invalid` | `boolean` | `true`, `false` | `false` | Error presentation (`aria-invalid` attribute → destructive border/ring; pair with a `.field-error`). |
| `type` | `enum` | `text`, `email`, `password`, `search`, `number` | `text` | Input behavior / mobile keyboard (semantic type values). |
| `size` | `enum` | `xs`, `sm`, `md`, `lg`, `xl` | `md` | Height ladder via `data-size`; the unsized default IS the md step (2.25rem). |
```
