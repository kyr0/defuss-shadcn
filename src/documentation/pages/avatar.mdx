<PageHeader slug="avatar" title="Avatar" component="avatar">
  An image element with a fallback for representing the user. Supports sizes, status badges, and avatar groups.
</PageHeader>

<SkillPanel component="avatar">
  <SkillField label="Native basis">
<SkillText><code>&lt;img&gt;</code> element wrapped in a container <code>&lt;span&gt;</code> with a text fallback for when the image fails to load.</SkillText>
  </SkillField>

  <SkillField label="Web Platform APIs">
<SkillRow>
    <ApiPill href="https://developer.mozilla.org/en-US/docs/Web/HTML/Element/img" title="image element with `onerror` fallback"><code>&lt;img&gt;</code></ApiPill>
    <ApiPill href="https://developer.mozilla.org/en-US/docs/Web/CSS/:has" title="toggle fallback visibility based on image state"><code>:has() selector</code></ApiPill>
  </SkillRow>
  </SkillField>

  <SkillField label="Classes">
<SkillRow>

    <code>.avatar-fallback</code>
    <code>.avatar-badge</code>
    <code>.avatar-group</code>
    <code>.avatar-group-count</code>
  </SkillRow>
  </SkillField>

  <p class="text-muted-foreground" style="margin:0 0 0;">• Avatar badge should use <code>aria-label</code> to convey status when meaningful</p>

<StatesSection>
  <p class="text-sm text-muted-foreground" style="margin:0 0 0.75rem;">Named states via the shared State API, driven per instance through the bound <code>api</code>:</p>
  <ul class="text-sm text-muted-foreground" style="margin:0 0 0.75rem;padding-left:1.25rem;">
    <li><code>default</code> — image shown (or fallback when there is no image)</li>
    <li><code>error</code> — the broken-image look, forced without a network failure (same DOM changes a real <code>error</code> event makes)</li>
  </ul>
  <p class="text-sm text-muted-foreground">The demo element carries <code>data-state-demo</code>; <code>bun run screenshots</code> drives it via <code>el.api.setState(name)</code> and captures <code>screenshots/\{mode\}/avatar-\{state\}.png</code>.</p>
</StatesSection>
