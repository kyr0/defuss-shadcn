<p class="text-sm text-muted-foreground">The <code>&lt;textarea&gt;</code> you edit is the <code>srcdoc</code> a sandboxed <code>&lt;iframe&gt;</code> runs, so the code shown and the code run cannot differ. With a component schema the card generates state controls that drive the previewed component and read it back. It ships as its own <strong>wysiwyg bundle</strong> - <code>wysiwyg.css</code> + <code>wysiwyg.js</code>, loaded after <code>all.css</code> / <code>all.js</code> - kept out of <code>all.*</code>, so pages without an editor do not pay for it. The first of the WYSIWYG Editors; its markup and API carry the name <code>code-example</code>.</p>

## Installation

The component ships in the extra bundle - include it after the system:

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/kyr0/defuss-shadcn@latest/dist/components/all.min.css">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/kyr0/defuss-shadcn@latest/dist/components/wysiwyg.min.css">
<script type="module" src="https://cdn.jsdelivr.net/gh/kyr0/defuss-shadcn@latest/dist/components/all.min.js"></script>
<script type="module" src="https://cdn.jsdelivr.net/gh/kyr0/defuss-shadcn@latest/dist/components/wysiwyg.min.js"></script>
```

```html example label="A playground with an API" hint="el.api.setState('code' | 'state' | 'fullscreen' | 'default'), df$.shadcn.codeExample.setSource / reset / viewport drive the card; code-example-change reports every rerun of the preview."

    <button class="btn" data-size="sm" data-variant="outline" id="cx-source">Show the source</button>
    <button class="btn" data-size="sm" data-variant="outline" id="cx-tablet">Tablet</button>
    <button class="btn" data-size="sm" data-variant="outline" id="cx-reset">Reset</button>
  </div>
  <div class="code-example" id="cx-play" aria-label="Playground">
    <textarea>

<script>
  document.addEventListener('DOMContentLoaded', () => {
    const lib = df$.shadcn.codeExample;
    const card = df$('#cx-play').get(0);
    card.addEventListener('code-example-change', (e) => {
      df$('#cx-log').text('code-example-change (' + e.detail.origin + '): ' + e.detail.source.trim().length + ' characters');
    });
    df$('#cx-load').on('click', () => lib.setSource(card, '<div class="card">\n  <div class="card-header">\n    <h3 class="card-title">A card</h3>\n    <p class="card-description">Loaded with setSource().</p>\n  </div>\n</div>'));
    df$('#cx-source').on('click', () => card.api.setState(card.api.getState().name === 'code' ? 'default' : 'code'));
    df$('#cx-tablet').on('click', () => lib.viewport(card, 'tablet'));
    df$('#cx-reset').on('click', () => lib.reset(card));
  });
</script>
```

## Configuration

By default a preview loads the page's own stylesheets and inlines its `all.js` (or `core.js`). `configure()` replaces that - this site hands every preview its sheets as inlined text, lucide and the current theme:

```js
df$.shadcn.codeExample.configure({
  styles: ['https://example.com/app.css'],          // URLs (<link>) or { css } texts - or a function of the source
  scripts: [{ js: runtimeText }],                    // URLs (fetched, inlined) or { js } texts
  tail: '<script src="https://unpkg.com/lucide"></script>',
  theme: () => document.getElementById('theme-css').textContent,
  highlight: (code, language) => myHighlighter(code, language), // HTML of coloured spans
});
```

<StatesSection>
  <p class="text-sm text-muted-foreground m-0 mb-3">Named states via the shared State API, bound on each card:</p>
  <ul class="text-sm text-muted-foreground m-0 mb-3 ps-5">
    <li><code>default</code> - the preview alone, both panels closed</li>
    <li><code>code</code> - the source is open (and painted)</li>
    <li><code>state</code> - the state controls are open (cards with <code>data-schema</code>; without one it lands in <code>default</code>)</li>
    <li><code>fullscreen</code> - the card fills the screen; <code>config.panel</code> keeps a panel open below the stage</li>
  </ul>
  <p class="text-sm text-muted-foreground">Every config carries <code>source</code> - setting it reruns the preview. The first example carries <code>data-state-demo</code>; <code>bun run screenshots</code> drives the card inside it and captures <code>screenshots/\{mode\}/code-example-\{state\}.png</code>. A card's <code>el.preview</code> drives the component it previews.</p>

Machine contract - verified against <a class="link" href="../schemas/code-example.schema.json"><code>code-example.schema.json</code></a> by <code>bun run verify</code>:

```states
| State | Type | Values | Default | Description |
| --- | --- | --- | --- | --- |
| `code` | `boolean` | `true`, `false` | `false` | The source is open - `setState('code')`; off returns to `default`. |
| `state` | `boolean` | `true`, `false` | `false` | The state controls are open - `setState('state')` (a card with `data-schema`). |
| `fullscreen` | `boolean` | `true`, `false` | `false` | The card fills the screen - `setState('fullscreen')`; off (or Escape) returns to `default`. |
```
