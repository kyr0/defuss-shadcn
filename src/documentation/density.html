Density

Compactness is an explicit whitespace policy—not a global zoom factor. Keep typography, geometry and target sizes independent.

Opt in to interface density

Density changes whitespace, not display resolution. The presets are adjustable design choices: compact 0.75, comfortable 1, spacious 1.25. They inherit into descendants; an inner density attribute starts a new density context.

What changes—and what does not

QuantityDensity behavior
Numeric gaps, padding, margins; stack gap; default container guttersScaled.
Numeric widths, heights, square sizes, icon dimensionsUnchanged.
Fonts and line heightsUnchanged.
Literal px spacing, automatic margins, percentage sizesUnchanged.
Existing button/input recipes and their fixed dimensionsUnchanged until explicitly migrated.
Interaction target minimaIndependent CSS-pixel constraints.

Customize a context

CSS
.dense-inspector { --layout-density: 0.9; }

/* Component-owned opt-in recipe. No changes to existing .btn rules. */
.inspector-action {
  min-inline-size: 44px;
  min-block-size: 44px;
  padding-inline: calc(var(--size-base) * 3 * var(--layout-density));
}

Use a valid nonnegative number. Numeric spacing clamps negative density to zero; invalid CSS token types are not runtime-validated. Named size aliases stay geometric. Do not express density by changing the root font size or devicePixelRatio.

Pointer capability is a separate policy

CSS
.inspector-action {
  min-inline-size: 44px;
  min-block-size: 44px;
}

@media (any-pointer: coarse) {
  .inspector-action { padding-inline: 1rem; }
}

The example already keeps a 44px target baseline; the media query only adds breathing room. any-pointer: coarse can detect an available coarse pointer on a hybrid device, but it is not a complete description of a user’s access needs. Keep controls usable without that signal. Media Queries: available pointer capabilities
