Container

Centered, bounded content with logical gutters. Query containment remains a separate, explicit choice.

Bound and center content

container has a 100% border-box inline size, an 80rem maximum, automatic inline margins and four density-adjusted base units of inline padding. The cap includes gutters. It does not change display or create a query container.

Outer container: max-width clamps, gutters keep content off the edge.

Nested: its own cap and gutter, not the outer ones.

HTML
<main class="container" style="--layout-max:64rem;--layout-gutter:1.5rem;">
  <h1>Workspace</h1>
  <p>Content stays bounded without measuring the viewport in JavaScript.</p>
</main>

Customize each instance

CSS
.reading-area {
  --layout-max: 70ch;
  --layout-gutter: clamp(1rem, 3vw, 2rem);
}

The maximum and gutter reset on every nested container. Override each root deliberately; an outer width limit is not inherited configuration. Container centering, gutters and the fixed 80rem default are extensions to Tailwind’s container behavior. A narrow container does not make overflowing child content safe automatically.

A query boundary is explicit

HTML
<section class="container query">
  <div class="flex flex-col gap-4 account-actions">
    <button class="btn" type="button">Profile</button>
    <button class="btn" type="button">Security</button>
  </div>
</section>
CSS
@container layout (inline-size >= 32rem) {
  .account-actions { flex-direction: row; }
}

The query selects the nearest ancestor named layout. It styles a descendant, not the query container itself. Inline-size containment changes intrinsic sizing, so it is opt-in; a shrink-to-fit query wrapper needs an externally determined width. Use literal query thresholds; custom properties are not breakpoint variables in size-query conditions.
